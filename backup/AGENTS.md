# 全局工作约定

## 网络搜索优先级

需要联网搜索时，**优先使用 `mcp__glm-websearch__websearch` 工具**。

它是本地多引擎降级链（Bing → AnySearch → Exa → Parallel），对中文查询和大陆网络环境更友好，且失败时自动降级、结果带引用来源。

- 内置 `WebSearch` 工具仅作后备：只在 `mcp__glm-websearch__websearch` 不可用（MCP 未连接）或调用失败时使用
- 两者都可用时先走 MCP，一次失败先看降级轨迹，确认真失败再退内置

## 批量并行任务

当一个请求可以分解为**多个相互独立、互不重叠**的并行子任务（分开的分析、互不重叠区域的逐模块修改、批量查询）时，优先用 `swarm` 工作流（`CreateWorkflow` 的 `saved: { name: "swarm", args }`），而不是反复单个派遣子代理：共享指令在 `prompt_template` 里用 `{{item}}` 占位符写一次，各子任务的差异部分列在 `items`，最后把逐项结果综合成一个答案。

- **拆分质量决定批次质量**。每条 item 必须自包含：子代理只能看到自己展开后的 prompt，所以要写清输入、预期输出、完成判据——写成陌生人不用追问就能执行的程度。好的拆分如"补充测试覆盖"：每个顶层模块一条，写明模块路径、所用测试框架、"新测试通过"的判据；坏的拆分："写测试""修 bug""清理一下"。
- **有依赖或共享可变状态的子任务绝不并行**：那些自己做或放后一批。
- 所有子任务都需要的相同背景（项目约定、文件清单）通过 `shared_context` 传一次，不要逐条重复。
- 大批次或不熟悉的拆分，先 `dry_run: true` 看展开后的每条 prompt 再花额度执行。
- 需要对某条结果追问时，用 `followups: [{index, followup}]`，该条目沿用原上下文。
- 传输类失败（网络、限流）由工作流运行时自动重试，只有重试耗尽才会在结果里标为失败。
- **成本路由（重要）**：启动任何工作流（CreateWorkflow / saved）前，先读 `~/.zcode/v2/agents-state.json` 的 `builtInModelSelectionOverrides.general-purpose`（用户为子代理设的默认模型绑定，值可能变化，**每次启动现读、不要凭记忆**）；有绑定则把它作为 `subagent_model` 传入，让工作流子代理与 Agent 子代理用同一个模型；无绑定则不传。工作流子代理默认会跟随会话模型（主套餐），不传即烧主套餐。
